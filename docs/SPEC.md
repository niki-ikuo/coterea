# Coterea 製品仕様書（Windows）

**Coterea** — The collaborative AI text editor.  
人と AI が、ともに書き、ともに創る場所。

| 項目 | 内容 |
|------|------|
| 文書 | 製品仕様（フェーズ1 / フェーズ2） |
| 読み | コテリア / koh-TEH-ree-uh |
| 名称 | [coterea-naming.md](./coterea-naming.md) |

---

## 1. プロダクト定義

| 項目 | 内容 |
|------|------|
| 名称 | **Coterea** |
| プラットフォーム | Windows 10/11（x64） |
| コンセプト | サーバーを持たない、ローカルファイル向けの **リアルタイム共同編集テキストエディタ**。フェーズ2で汎用 LLM API を接続し、チャットから文書を編集する |
| 対象 | メモ・文書・Markdown などテキストを扱う人。コード専用 IDE ではない |
| 非目標 | Coterea 運営のクラウド、アカウント必須、自社中継サーバー |

**「サーバーを必要としない」の意味**

- Coterea 側のバックエンド・中継・サインイン基盤は置かない。
- 共同編集は **端末同士の P2P**（同一 LAN を主想定）で成立させる。
- フェーズ2の AI は、利用者が用意した **外部 LLM API**（OpenAI 互換など）へ各端末から直接接続する。これは Coterea のサーバーではない。
- オフラインでも、単体編集と（LAN 内の）共同編集は動く。AI だけオンライン（またはローカル LLM）が必要。

---

## 2. フェーズ分割

| フェーズ | 名前 | ゴール |
|----------|------|--------|
| **フェーズ1** | テキストの共同編集 | 複数ファイルをタブで開き、プレーンテキスト / Markdown 等を編集し、**サーバーなしでリアルタイム共同編集**できる |
| **フェーズ2** | AI でのテキスト共同編集 | 右ペインのチャットで汎用 AI と対話し、提案を文書へ適用する。適用結果は **同じ共同編集セッション上の全員に見える** |

フェーズ1で右ペインは「共同編集」（参加者・招待）。フェーズ2で同じ右ペインに AI チャットを載せる。左がエディタであることは両フェーズで変えない。

## 3. 画面構成

最終形（フェーズ2）:

```
┌─────────────────────────────────────────────────────────────┐
│  メニュー  [ファイル] [編集] [表示] [共同編集] [設定]         │
├──────────────────────────────────┬──────────────────────────┤
│  タブ: notes.md ●  memo.txt      │  AI チャット             │
│──────────────────────────────────│  （フェーズ1は参加者）   │
│                                  │  ┌────────────────────┐  │
│         テキストエディタ         │  │ 会話 / 参加者一覧  │  │
│         （左ペイン）             │  └────────────────────┘  │
│                                  │  [入力欄]  [送信]        │
├──────────────────────────────────┴──────────────────────────┤
│  行:列 | 言語 | 共同編集: 接続 n人 | AI: 未設定 / 接続中      │
└─────────────────────────────────────────────────────────────┘
```

| 項目 | 仕様 |
|------|------|
| 既定サイズ | 1280×800、リサイズ可 |
| レイアウト | **2ペイン**（左エディタ 約 65% / 右パネル 約 35%）。境界ドラッグで幅変更。右パネルは折りたたみ可 |
| タブ | 左ペイン上部。複数ファイル。未保存は ●。並び替え・閉じる・ピン留めはフェーズ1では閉じるのみで可 |
| 右ペイン（フェーズ1） | セッション状態、自分の表示名、参加者（名前・色・カーソルファイル）、招待コードの発行 / 参加 |
| 右ペイン（フェーズ2） | 上記の要約（人数など）＋ **AI チャット**（履歴・入力・送信）。共同編集の詳細は「共同編集」メニューまたは右ペインのサブタブ |
| ステータスバー | 行/列、言語モード、共同編集の接続人数、AI 設定の有無 |

フォルダツリー・Git・クリップ用の左サイドバーは **本仕様の対象外**（後続）。ファイルは「開く」ダイアログとタブで扱う。

## 4. フェーズ1 — テキストの共同編集

### 4.1 エディタ

| 機能 | 仕様 |
|------|------|
| エンジン | Monaco Editor（VS Code と同系） |
| 操作 | 新規・開く・保存・名前を付けて保存・閉じる、Undo/Redo、検索・置換 |
| 対象ファイル | テキストとして開くもの。最低限 **`.txt` / `.md` / `.markdown`**。加えて UTF-8 の `.json` `.csv` `.html` `.css` `.js` `.ts` `.py` 等はシンタックス付きで編集可 |
| エンコーディング | UTF-8（BOM なし）を既定。他エンコーディングはフェーズ1対象外 |
| タブ | 複数ファイル同時。アクティブタブが左ペインの編集対象 |
| 保存 | 単独編集時は明示保存。共同編集中は **デバウンス自動保存**（例: 500–1500ms）でローカルファイルへ反映し、他者の編集もディスクに書く |
| 閉じる / 終了 | 未保存（共同編集の未フラッシュ含む）なら確認 |

バイナリ・Office・PDF は開かない（OS 既定アプリへは後続）。

### 4.2 ファイルとタブ

| 機能 | 仕様 |
|------|------|
| 開く | ファイル選択ダイアログ。複数選択可。既に開いているパスは既存タブへ切替 |
| 新規 | 未保存バッファ。初回保存でパスが付く |
| 最近使ったファイル | メニューに数件（任意だが推奨） |
| 文字数 | 1ファイルあたり目安 **2MB / 約 10 万行未満** を動作保証の上限とする（超える場合は警告） |

### 4.3 リアルタイム共同編集（サーバーなし）

**モデル:** 各テキストファイルは **CRDT 文書**（推奨: Yjs）。エディタ操作は CRDT に変換し、ピアへ送る。同時編集でも上書き戦争にしない。

| 項目 | 仕様 |
|------|------|
| 同期単位 | **タブごと（ファイルパスごと）**。セッションに参加しているピアは、ホストが共有したファイルを同じ内容で見る |
| 接続 | **P2P**。Coterea のクラウドは使わない |
| 発見（主） | 同一 LAN の mDNS / UDP ブロードキャストでセッションを見つける |
| 参加（副） | 招待コード（短いルーム ID）を口頭・チャットで渡し、同じ LAN 上で接続。NAT 越えのインターネット直結はフェーズ1の必須としない |
| シグナリング | 自前サーバーは置かない。LAN 内のピア探索で SDP/接続情報を交換する |
| 伝送 | WebRTC DataChannel または同等の暗号化チャネル。可能なら DTLS |
| プレゼンス | 参加者の表示名、色、キャレット位置、選択範囲を他者のエディタに表示 |
| 権限 | フェーズ1は全員が編集可（読み取り専用は後続） |
| ホスト | 最初に「共有を開始」した端末。ホスト切断時は **残ピアでセッション継続**できること（ホスト単一障害を避ける）。困難なら「ホスト切断でセッション終了」を明示し、フェーズ1.1 で改善 |
| 競合 | CRDT で自動解消。意味的な文のぶつかりはユーザーが目で直す |
| オフライン | ピア不在時は通常のローカル編集。再接続後に差分を合流 |

**共有の流れ（フェーズ1）**

1. ホストがファイルを開く → 「共同編集を開始」
2. 右ペインに招待コードと（LAN 上の）セッション名が出る
3. 参加者が「参加」しコードを入力（同一 LAN）
4. 参加者側に同じ内容のタブが開く（未保存の新規なら、参加者はメモリ上の文書として開く。パスはホスト側のローカルパス）
5. 双方のキー入力がほぼリアルタイムに反映される

**パスの扱い:** 各端末のディスクパスは異なってよい。共有の同一性はセッション ID + 文書 ID。参加者は「名前を付けて保存」で自分のディスクへコピーできる。

### 4.4 フェーズ1 の設定

| 項目 | 既定 |
|------|------|
| 表示名 | OS のユーザー名（変更可） |
| キャレット色 | 参加者ごとに自動割当 |
| 共同編集 | ON（開始するまで未接続） |

### 4.5 フェーズ1 完了条件

- [ ] テキスト / Markdown をタブで複数開き、単独で編集・保存できる
- [ ] 同一 LAN の 2 台以上で、同じ文書を同時編集し、数秒以内に双方へ反映される
- [ ] 同時に離れた箇所を編集しても、内容が壊れない（CRDT）
- [ ] 他者のキャレットが見える
- [ ] Coterea 独自サーバーを起動しなくても共同編集できる
- [ ] インストーラ（NSIS）で Windows に入れられる

## 5. フェーズ2 — AI でのテキスト共同編集

フェーズ1のエディタと P2P 共同編集は維持する。AI は **もう一人の共同編集者**として文書に入る（実際の書き込みは、提案をユーザーが承認したあと CRDT 経由）。

### 5.1 AI チャット（右ペイン）

アクティブファイルをコンテキストに載せ、差分プレビューしてから適用する。Agent ループ・ターミナル・ツール実行は **対象外**。

| 機能 | 仕様 |
|------|------|
| 入力 | マルチライン。Enter 送信 / Shift+Enter 改行 |
| コンテキスト | ①アクティブタブの全文 ②選択範囲があればそれを優先して明示 |
| ストリーミング | トークン単位で表示 |
| 履歴 | 端末ローカル（アプリ設定ディレクトリ）。ワークスペースサーバーは無いので **端末ごと**。共同編集相手とチャット履歴は共有しない（文書だけ共有） |
| モード | **Ask**（説明のみ、文書を変えない） / **Edit**（変更案を出し、承認後に適用） |

コンテキスト例:

```
[現在のファイル: notes.md]
（本文）

[選択範囲]
（あれば）

[ユーザー]
導入を短くして
```

### 5.2 提案の適用と共同編集

AI の Edit は **ローカルでプレビュー → ユーザー承認 → CRDT に適用** する。承認した端末から P2P で他者へ届く。AI がピアに直接書き込まない。

| 手順 | 仕様 |
|------|------|
| 1. プレビュー | 追加=緑、削除=赤の差分 |
| 2. 適用 | ファイル全体置換、または選択範囲置換（フェーズ2 MVP はこの2つ） |
| 3. 拒否 | 文書は不変 |
| 同時編集 | プレビュー生成中に他者が編集した場合は、適用前に差分を再計算するか、衝突を警告してやり直す |

Ask 中も他者は編集してよい。

### 5.3 LLM 接続（利用者の API）

Coterea はモデルをホストしない。

| 項目 | 既定 |
|------|------|
| 方式 | OpenAI 互換 Chat Completions（SSE） |
| プリセット | OpenAI / Gemini / DeepSeek / Groq / OpenRouter / **Ollama（ローカル）** / カスタム Base URL |
| API Key | 端末内で暗号化保存。Renderer から直接外部へ出さない（Main 経由） |
| モデル | プリセット候補 + 自由入力。既定例 `gpt-4o-mini` |
| 温度 | 0.2 |
| Max tokens | 8192（設定で変更可） |

Ollama 等のローカル LLM なら、AI もインターネットなしで使える。

### 5.4 フェーズ2 完了条件

- [ ] API Key を設定し、右ペインでストリーミングチャットできる
- [ ] Ask でアクティブファイルについて質問できる
- [ ] Edit の差分を承認すると、左の文書が更新される
- [ ] 共同編集中に一方が AI 適用すると、他方のエディタにも同じ変更が入る
- [ ] Key 未設定でもフェーズ1の編集・共同編集は使える

## 6. 技術スタック（推奨）

Windows デスクトップと Monaco を優先する。

| 層 | 技術 |
|----|------|
| UI | React + TypeScript |
| シェル | Electron 33+ |
| エディタ | Monaco Editor |
| 共同編集 | **Yjs** + Monaco バインディング |
| P2P | WebRTC DataChannel。LAN 発見は mDNS（例: Bonjour / `bonjour-service`）または UDP |
| 状態 | Zustand |
| ビルド | electron-vite |
| 配布 | electron-builder（NSIS） |
| AI | Main プロセスから fetch + SSE |

**Electron を選ぶ理由:** Monaco との相性、Windows パッケージの成熟、MVP 速度。

**後続の代替:** Tauri はバイナリは小さいが、Monaco + P2P のコストが高い。フェーズ1–2では採用しない。

## 7. アーキテクチャ

```
┌─────────────────────────────────────────────────┐
│                 Renderer                         │
│  ┌──────────────┐     ┌─────────────────────┐   │
│  │ Monaco+Yjs   │     │ 右ペイン             │   │
│  │ タブ / 編集  │     │ P1: 共同編集         │   │
│  └──────┬───────┘     │ P2: AI チャット      │   │
│         │             └──────────┬──────────┘   │
│         └────────────┬───────────┘               │
│                   Zustand                        │
└──────────────────────┬──────────────────────────┘
                       │ IPC
┌──────────────────────┴──────────────────────────┐
│                   Main                           │
│  fs  │  P2P（発見・WebRTC）  │  settings  │  AI  │
└─────────────────────────────────────────────────┘
        │  LAN ピア（サーバーなし）
        ▼
   他の Coterea 端末
```

### IPC（最小）

| チャンネル | 方向 | 用途 |
|------------|------|------|
| `fs:open` / `read` / `write` / `saveAs` | R→M | ファイル |
| `collab:start` / `join` / `leave` | R→M | セッション |
| `collab:update` | 双方向 | CRDT 更新バイナリ |
| `collab:awareness` | 双方向 | カーソル・名前 |
| `settings:get` / `set` | R→M | 表示名・API Key 等 |
| `ai:chat`（フェーズ2） | R→M | SSE ストリーム |

Renderer は生のソケットや API Key を持たない。

## 8. データモデル（最小）

```typescript
interface OpenTab {
  id: string;
  path: string | null; // 未保存は null
  language: string;
  ydoc: unknown; // Y.Doc
  isDirty: boolean;
}

interface Peer {
  id: string;
  displayName: string;
  color: string;
}

interface CollabSession {
  roomId: string;
  peers: Peer[];
  role: "host" | "guest";
}

interface AppSettings {
  displayName: string;
  // フェーズ2
  providerId?: string;
  apiBaseUrl?: string;
  model?: string;
  temperature?: number;
}
```

API Key は設定オブジェクトに平文で載せない（Main の安全なストア）。

ローカル保存の目安:

```
%APPDATA%/Coterea/
  settings.json      # Key 以外
  secrets.bin        # 暗号化 Key（フェーズ2）
  chat-history.json  # フェーズ2
  recent-files.json
```

共同編集の CRDT 本体は、保存時にプレーンテキストへ落としてユーザーのファイルに書く。独自の必須クラウド領域は作らない。

## 9. 非機能要件

| 項目 | 目標 |
|------|------|
| 起動 | コールドスタート 5 秒以内（目安） |
| 共同編集遅延 | 同一 LAN・小文書で往復 **500ms 未満**を目標 |
| 同時人数 | フェーズ1は **2〜4人** を保証。それ以上は最善努力 |
| メモリ | 小文書数タブで 400MB 未満を目安 |
| インストーラ | NSIS、スタートメニュー |
| セキュリティ | Key は平文保存しない。P2P は招待コードを知らない端末を入れない。LAN 上の盗聴耐性は「招待コード + チャネル暗号化」まで（公開 Wi-Fi は非推奨と明記） |
| オフライン | 編集は可。共同編集は LAN 内ピアがいれば可。クラウド AI は不可（Ollama は可） |
| アクセシビリティ | タブ・ボタンはキーボード操作可（最低限） |

## 12. まとめ

Coterea は Windows 上の **左エディタ・右パネル** のテキストアプリである。

1. **フェーズ1** — タブで複数のテキストを開き、**サーバーなし P2P** でリアルタイム共同編集する。
2. **フェーズ2** — 利用者が繋いだ汎用 LLM とチャットし、承認した編集を **同じ CRDT 文書** に載せて全員で共有する。

本質は「ローカルファイル + リアルタイムな人の共同編集 +（任意の）AI という共同編集者」である。
