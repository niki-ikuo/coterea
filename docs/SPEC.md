## 1. プロダクト定義


| 項目       | 内容                                                                               |
| -------- | -------------------------------------------------------------------------------- |
| 名称       | **Coterea**                                                                      |
| プラットフォーム | Windows 10/11（x64）                                                               |
| コンセプト    | サーバーを持たない、ローカルファイル向けの **リアルタイム共同編集テキストエディタ**。フェーズ2で汎用 LLM API を接続し、チャットから文書を編集する |
| 対象       | メモ・文書・Markdown などテキストを扱う人。コード専用 IDE ではない                                         |
| 非目標      | Coterea 運営のクラウド、アカウント必須、自社中継サーバー                                                 |


**「サーバーを必要としない」の意味**

- Coterea 側のバックエンド・中継・サインイン基盤は置かない。
- 共同編集は **端末同士の P2P**（同一 LAN を主想定）で成立させる。
- フェーズ2の AI は、利用者が用意した **外部 LLM API**（OpenAI 互換など）へ各端末から直接接続する。これは Coterea のサーバーではない。
- オフラインでも、単体編集と（LAN 内の）共同編集は動く。AI だけオンライン（またはローカル LLM）が必要。

## 2. フェーズ分割


| フェーズ      | 名前            | ゴール                                                             |
| --------- | ------------- | --------------------------------------------------------------- |
| **フェーズ1** | テキストの共同編集     | 複数ファイルをタブで開き、プレーンテキスト / Markdown 等を編集し、**サーバーなしでリアルタイム共同編集**できる |
| **フェーズ2** | AI でのテキスト共同編集 | 右ペインで **Ask / Edit / Agent** を切替し、提案を文書へ適用する。適用結果は **同じ共同編集セッション上の全員に見える** |


左がエディタであることは両フェーズで変えない。右ペインは **1つのパネル** をフェーズで中身を替える。フェーズ1は共同編集の操作が本体。フェーズ2は **AI チャット（会話スレッド）が本体**、共同編集はヘッダーの要約と折りたたみに退ける（フルの共同編集画面とチャットを同時に並べない）。「セッション」という語は共同編集の接続状態にだけ使い、会話の単位は **スレッド** と呼ぶ。

## 3. 画面構成

最終形（フェーズ2）:

```
┌─────────────────────────────────────────────────────────────┐
│  メニュー  [ファイル] [編集] [表示] [ヘルプ]                   │
├──────────────────────────────────┬──────────────────────────┤
│  タブ: notes.md ●  memo.txt      │  2人 · ハブ  [共同編集▾] │
│  （右上: このファイルのアバター）  │  会話: 導入を短く +  │
│──────────────────────────────────│──────────────────────────│
│                                  │  このスレッドの履歴        │
│         テキストエディタ         │  Ask │ Edit │ Agent     │
│         （左ペイン）             │  [入力欄]        [送信]  │
├──────────────────────────────────┴──────────────────────────┤
│  行:列 | 言語 | 共同編集: 接続 n人 | AI: 未設定 / 接続中      │
└─────────────────────────────────────────────────────────────┘
```

フェーズ1は同じ右ペインの **全体が共同編集**（チャット欄はない）。フェーズ2でチャットを載せるとき、共同編集の詳細 UI をチャットの下に積み重ねない。会話の切替はチャット側のスレッドタブで行う。


| 項目          | 仕様                                                                                             |
| ----------- | ---------------------------------------------------------------------------------------------- |
| 既定サイズ       | 1280×800、リサイズ可                                                                                 |
| レイアウト       | **2ペイン**（左エディタ / **右パネル**）。境界ドラッグで幅変更。右パネルは **初期非表示**。表示状態は次回起動に引き継ぐ。表示メニューはフェーズ1「共同編集パネル」、フェーズ2で **「右パネル」**（ショートカットは同じ） |
| タブ          | 左ペイン上部。Cursor 風のフラットなタブ（ファイル種別アイコン、ファイル名、ホバーで閉じる、未保存は閉じる位置のドット）。Markdown の切替はタブ直下のバー           |
| 人数の常時表示   | 画面右上に **このファイルの編集人数**（CodiMD 風の重なりアバター）。クリックで名前と色。パネルを閉じても見える                         |
| 右ペイン（フェーズ1） | 共同編集が本体。状態、自分の表示名、参加者（名前・色・カーソルファイル）、待ち受け / 手動接続、共有中ファイル。同一 LAN は自動接続 |
| 右ペイン（フェーズ2） | **チャットが本体**。共同編集は **ヘッダー1行** と **「共同編集」折りたたみ**。チャット内は **会話スレッドタブ** と **Ask / Edit / Agent** 切替。共同編集の詳細とチャットを同時に全面表示しない |
| ステータスバー     | 行/列、言語、Markdown表示、文字コード、共同編集の接続人数、AI 設定の有無                                                     |


フォルダツリー・Git・クリップ用の左サイドバーは **本仕様の対象外**（後続）。ファイルは「開く」ダイアログ、エクスプローラーの「Coterea で開く」、タブで扱う。

### 4.2 ファイルとタブ

| 開く        | ファイル選択ダイアログ。複数選択可。既に開いているパスは既存タブへ切替。エクスプローラーの右クリック **「Coterea で開く」**（インストーラが登録。既定アプリにはしない） |

### 4.3 リアルタイム共同編集（サーバーなし）

**モデル:** 各テキストファイルは **CRDT 文書**（推奨: Yjs）。エディタ操作は CRDT に変換し、ピアへ送る。同時編集でも上書き戦争にしない。


| 項目     | 仕様                                                                                                   |
| ------ | ---------------------------------------------------------------------------------------------------- |
| 同期単位   | **ファイルごと**。**同一の実体**を開いているタブだけ同期する（フルパス・ファイル名だけ・UNC・マップドライブなど表記が違っても同一視）。無題バッファと、相手が開いていないファイルは共有しない |
| 接続     | **P2P**。Coterea のクラウドは使わない                                                                           |
| 発見（主）  | 同一 LAN の UDP プレゼンス。一人のときは共同編集セッションを組まない                                                              |
| 参加     | 同一 LAN の Coterea を自動検出して接続。招待コードは使わない                                                                |
| シグナリング | 自前サーバーは置かない。LAN 内のピア探索で接続情報を交換する                                                                     |
| 伝送     | TCP（LAN）。ファイル同期はその上に載せる                                                                              |
| プレゼンス  | 参加者の表示名、色、キャレット位置、選択範囲を他者のエディタに表示                                                                    |
| 権限     | フェーズ1は全員が編集可（読み取り専用は後続）                                                                              |
| ホスト    | **先にいた人（最古参）がハブ**。2人目は参加側。ハブは単一の TCP 中継点（仕様）。切断時は残りの最古参が引き継ぐ。一人に戻ったらハブは止める。切れ目の再接続は仕様どおり             |
| 競合     | 接続中の同時編集は CRDT で自動解消。意味的な文のぶつかりはユーザーが目で直す                                                            |
| オフライン  | ピア不在時は通常のローカル編集。再接続時は正本の全文スナップショットで Y.Doc を合わせる（独立に初期化した文書はマージしない）。接続後は増分同期                          |


**共有の流れ（フェーズ1）**

1. 1人目はファイルを開いて普通に編集する（共同編集セッションは組まない）
2. 同一 LAN にもう1人 Coterea を開くと、**先にいた人がハブ**になり自動接続する
3. **同じ実体のファイル**を双方が開いているときだけ、そのファイルが同期される
4. ハブが終了しても、残っている最古参がハブを引き継ぐ。最後の1人になったらハブは止まる



#### 4.3.1 ファイル同一性（検討の結論）

同期の単位は **ファイル名ではなく、同じ実体を開いていること**。パス文字列の一致は用いない。無題バッファは共有しない。相手が開いていないファイルは各端末のローカル編集のまま。片方は「名前を付けて保存」で自分のディスクへコピーできる。

**同一とみなす**

- フルパス、ファイル名だけ、`\\コンピュータ名\...`、マップドライブ、`subst`、`\\?\` など、**表記が違っても同じファイル実体**
- 自ホストの管理シェア（`\\自分\c$\...`）と `C:\...`
- ハードリンクなど、同じボリューム上の同じファイルインデックス

**同一とみなさない**

- 別 PC 上の同名ローカルコピー（どちらも `C:\work\a.txt` でも別物）
- 無題同士
- 判定に自信がないとき（誤って混ぜない）

**正本の判定（優先順）**


| 順   | 手段                                                                           | 役割                           |
| --- | ---------------------------------------------------------------------------- | ---------------------------- |
| 1   | 開いたハンドルが返す最終パス（Windows: `GetFinalPathNameByHandle` とデバイス名解決）                 | マップドライブ・UNC・拡張パスなどの表記を一系統にする |
| 2a  | ローカルファイル: ホスト識別 + ボリューム + ファイルインデックス                                         | 同じディスク上の同じエントリ               |
| 2b  | ネットワークファイル: 正規化 UNC（ホストは短い名前の小文字、IPv4 はそのまま。自ホストならローカルへ戻す。自 NIC の IP もエイリアス） | 共有上の同じパス                     |
| 3   | 上記で鍵が重ならない                                                                   | **同期しない**                    |


`net share` の一覧は、自ホストの共有名エイリアス用の補助に限る。`net use` / `subst` の文言パースは使わない（ドライブの展開は `QueryDosDevice`）。識別子が一つも取れないタブは同期しない。文書の正本 ID（Yjs）は、そのファイルを先に開いていた側（最古参）に合わせる。

**実装（Windows）**

Main が対象を `CreateFile` で開き、`GetFinalPathNameByHandle`・`QueryDosDevice`・`GetFileInformationByHandle`・`GetDriveType` で識別子を作る。Renderer はパス文字列で照合しない。

**採用しない（フェーズ1）**


| 案                                       | 判断  | 理由                                                                          |
| --------------------------------------- | --- | --------------------------------------------------------------------------- |
| ベース名一致（`notes.md` なら同期）                 | 不採用 | 別場所の同名ファイルまで混ざる                                                             |
| フォルダに永続 UUID                            | 不採用 | フォルダコピーで別実体が同一になる。Git を汚す                                                   |
| 開いている間だけの隣ファイル（Word の `~$` 型。誰もいなければ消す） | 不採用 | 表記ゆらぎは最終パスで足りる。自動合流では残置マーカーの誤信が危険。書けない場所では使えず正本が二重になる。「最後の 1 人が消す」は P2P で脆い |


二重シェア名・DFS など、最終パスでも足りない事例が実地で出たら、一時マーカーは **補助キー** として再検討する。正本にはしない。

#### 4.3.2 同期プロトコル（実装）

Hub（Main）は Yjs を解釈しない TCP 中継。開いているファイルの照合は `files-manifest`（`fileIds` の重なり）。別系統の DocMeta ブロードキャスト（`collab:setDocs`）は持たない。


| メッセージ                           | 用途                                                                   |
| ------------------------------- | -------------------------------------------------------------------- |
| `yjs`                           | 接続後の増分 CRDT                                                          |
| `yjs-sync` / `yjs-sync-request` | 正本の全文スナップショット。参加・正本確立時に Y.Doc を置き換える                                 |
| `file-canonical`                | 最古参が正本 `docId` を宣言する                                                 |
| `files-manifest`                | 開いている実体の識別子一覧                                                        |
| `awareness`                     | キャレット・選択。`user.peerId` を載せる                                          |
| `peer-left`                     | ハブが全員へ中継。**離脱したピアの Awareness だけ消す**（残りのカーソルは残す）                      |
| `save-request` / `file-saved`   | ディスクへ書くのは正本側一人。`file-saved` は `mtimeMs` / `size` を付け、他端末の外部変更検知を抑止する |


外部エディタなど本当にディスクが変わったときだけ確認ダイアログを出す。共同編集の自動保存エコー、保存待ち中、ディスク内容が直前の保存内容と一致する場合は出さない。

#### 4.3.3 テスト

共同編集の核（ファイル同一性、ハブ選出、フレーム、Awareness のピア紐づけ、外部変更の判定）は `npm test` の単体テストで固定する。LAN 2 台の E2E は手動確認（手順: [collab-lan-e2e.md](./collab-lan-e2e.md)）。

## 5. フェーズ2 — AI でのテキスト共同編集

フェーズ1のエディタと P2P 共同編集は維持する。AI は **もう一人の共同編集者**として文書に入る（実際の書き込みは、提案をユーザーが承認したあと CRDT 経由）。モードは **Ask / Edit / Agent** の3つ。ターミナル・MCP・ディスク横断の RAG は対象外。

### 5.1 AI チャット（右ペイン）

アクティブな会話スレッドに、ドロップで添付したファイル／選択範囲をコンテキストとして載せる。文書を変える操作は差分プレビューしてから適用する。

**席の分け方（チャットと共同編集を重ねない）**

- 右パネルを開いたときの既定はチャット。ヘッダー直下が **会話スレッドのタブ**、その下が履歴、下が **モード切替 + 入力欄**。
- 共同編集の操作盤（待ち受けコピー、IP:ポート接続、共有ファイル一覧、LAN 注意）はヘッダーの **「共同編集」を開いたときだけ**出す。閉じるとチャットの面積を返す。
- 人数・接続の常時確認は、ヘッダー1行、右上アバター、ステータスバーに任せる。右ペインを「チャット画面 / 共同編集画面」の常時タブで二分しない。
- 会話スレッドは端末ローカル。共同編集の文書同期とは独立。Key 未設定でも共同編集の折りたたみとフェーズ1の編集は使える。

#### 会話スレッド

左のファイルタブとは別。**会話を分割して並行する**ためのもの。共同編集の接続（ハブ / 参加）とは無関係。


| 項目       | 仕様                                                                                          |
| -------- | ------------------------------------------------------------------------------------------- |
| 単位       | 1スレッド = 1本の会話（ユーザーと AI のメッセージ列）。送信は **アクティブなスレッド** にだけ載る。スレッドは最後に使ったモード（Ask / Edit / Agent）を覚える |
| UI       | チャット上部にフラットなタブ（タイトル、新規 `+`、ホバーで閉じる）。左のファイルタブと同じ操作感にする                                          |
| 新規       | 空のスレッドを作り、そこに切替。タイトルは最初のユーザー発言から自動（後から改名可）                                                    |
| 切替       | タブクリック。履歴・入力・未送信の下書きはそのスレッドに紐づく                                                               |
| 閉じる      | そのスレッドを削除（確認あり）。最後の1本は消せない（空にして残す）                                                              |
| 範囲       | **アプリ全体**（ファイルタブを切り替えてもスレッド一覧は残る）。コンテキストは **チャットにドロップした添付** があればそれ。未添付なら Ask / Edit は **カレントタブ**、Agent は **開いている全ファイル** |
| 共有       | **しない**。同じ文書を共同編集していても、相手のスレッドは見えない。見えるのは承認して文書に入った変更だけ                                         |
| 対象外      | スレッドの P2P 同期、枝分かれ、全文検索、文書へのコメントピン（後続のコメントスレッドとは別）                                            |


| 機能      | 仕様                                                                        |
| ------- | ------------------------------------------------------------------------- |
| 入力      | マルチライン。Enter 送信 / Shift+Enter 改行                                          |
| モード     | 入力欄の上で **Ask / Edit / Agent** を切替（スレッドごとに記憶）                                      |
| コンテキスト  | DnD カプセルがあればそれを使う。未添付なら Ask / Edit はカレントタブ（選択があればそれも）、Agent は開いている全ファイル。Edit の提案先は先頭の添付、なければカレント（§5.1.1） |
| ストリーミング | トークン単位で表示。Agent のツール呼び出しも履歴に出す                                                 |
| 履歴      | スレッド単位。端末ローカル。共同編集相手とは共有しない（文書だけ共有）                                      |
| 停止      | 生成中は停止できる。Agent ループも即座に打ち切る                                                     |


#### 5.1.1 モード（Ask / Edit / Agent）


| モード      | 文書を変えるか | 動き                                                                                          |
| -------- | ------- | ------------------------------------------------------------------------------------------- |
| **Ask**  | しない     | 説明・要約・質問のみ。差分カードは出さない。他者が編集していてもよい                                                      |
| **Edit** | 承認後のみ   | 1回の応答で変更案を1つ出す。対象は添付の主ファイル。プレビュー → 適用 / 拒否（§5.2）。連続ツール呼び出しはしない |
| **Agent** | 承認後のみ  | 添付本文を渡す。必要ならツールで他タブを読み、複数の変更案を出せる。複数依頼は `update_todo` で分割して順に処理。各変更は Edit と同じプレビューを経る。自動で CRDT に書き込まない。停止ボタンと **最大ステップ数（既定 12）** |


**Agent が使ってよいツール（フェーズ2）**


| ツール              | 内容                                                         |
| ---------------- | ---------------------------------------------------------- |
| `list_open_tabs` | 開いているタブの id・名前・言語                                         |
| `read_tab`       | 指定タブの本文（開いているものだけ。ディスクを勝手に歩かない）                            |
| `propose_edit`   | 指定タブへの変更案（全体置換または選択範囲置換）。履歴に差分カードを積む。適用はユーザー承認までしない         |
| `update_todo`    | 複数依頼を成果物単位のチェックリストに分割し、進捗（pending / in_progress / done / cancelled）を更新する。未完了がある間は終了しない |


**Agent がやってはいけないこと（フェーズ2）**

- ターミナル / シェル / プロセス起動
- MCP、ブラウザ、任意 URL の取得
- ワークスペース全体の検索（ファイルツリーが無い）
- ユーザー未承認のディスク書き込み、共同編集ピアへの直接書き込み

ツール実行は Main。Renderer は API Key も生ツールも持たない。モデルがツールを呼ぶたびに履歴へ「読んだ / 提案した」と出す。ステップ上限か停止でループを終える。

コンテキスト例（Ask / Edit）:

```
[添付ファイル: notes.md]
（本文）

[選択範囲（notes.md:12-18）]
（あれば）

[ユーザー]
導入を短くして
```

ファイルタブを入力欄へドロップ、エディタの選択範囲をドラッグ、または右クリック「チャットに追加」でカプセル化する。未添付時は Ask / Edit がカレントタブ、Agent が開いている全ファイルを対象にする。



### 5.2 提案の適用と共同編集

Edit と Agent の `propose_edit` は、どちらも **ローカルでプレビュー → ユーザー承認 → CRDT に適用** する。承認した端末から P2P で他者へ届く。AI がピアに直接書き込まない。Ask は適用手順に入らない。


| 手順       | 仕様                                                                 |
| -------- | ------------------------------------------------------------------ |
| 1. プレビュー | 追加=緑、削除=赤の差分。Agent は1ターンで複数カードが並んでよい                                   |
| 2. 適用    | ファイル全体置換、または選択範囲置換（フェーズ2 MVP はこの2つ）。Agent はカードごと、または「承認した分を一括適用」 |
| 3. 拒否    | そのカードの文書は不変。Agent の残りカードは残してよい                                      |
| 同時編集     | プレビュー生成中に他者が編集した場合は、適用前に差分を再計算するか、衝突を警告してやり直す                      |


Ask 中も他者は編集してよい。Agent 実行中も他者の編集は止まらない。適用の瞬間だけ §5.2 の衝突規則。

### 5.3 LLM 接続（利用者の API）

Coterea はモデルをホストしない。


| 項目         | 既定                                                                                |
| ---------- | --------------------------------------------------------------------------------- |
| 方式         | OpenAI 互換 Chat Completions（SSE）。Agent は **tool calling**（`tools` / `tool_choice`） |
| プリセット      | OpenAI / Gemini / DeepSeek / Groq / OpenRouter / **Ollama（ローカル）** / カスタム Base URL |
| API Key    | 端末内で暗号化保存。Renderer から直接外部へ出さない（Main 経由）                                           |
| モデル        | プリセット候補 + 自由入力。既定例 `gpt-4o-mini`。Agent はツール対応モデルを推奨（非対応なら Edit 相当に落とすかエラー）   |
| 温度         | 0.2                                                                               |
| Max tokens | 8192（設定で変更可）                                                                      |


Ollama 等のローカル LLM なら、AI もインターネットなしで使える。

### 5.4 フェーズ2 完了条件

- [ ] API Key を設定し、右ペインでストリーミングチャットできる
- [ ] 会話スレッドを新規・切替・改名・削除できる（履歴はスレッドごとに残る）
- [ ] Ask で添付ファイルについて質問でき、文書は変わらない
- [ ] ファイルタブと選択範囲をチャットへ DnD してカプセル添付できる
- [ ] Edit の差分を承認すると、添付した文書が更新される
- [ ] Agent が開いているタブを読み、複数の変更案を出せる。未承認では文書が変わらない。停止とステップ上限が効く
- [ ] 共同編集中に一方が AI 適用すると、他方のエディタにも同じ変更が入る（チャット履歴・Agent の思考は届かない）
- [ ] Key 未設定でもフェーズ1の編集・共同編集は使える
- [ ] 右ペインはチャット（スレッドタブ・モード切替含む）が本体で、共同編集の詳細は折りたたみ。両方のフル UI が同時に全面表示されない

## 6. 技術スタック（推奨）

Windows デスクトップと Monaco を優先する。


| 層    | 技術                                           |
| ---- | -------------------------------------------- |
| UI   | React + TypeScript                           |
| シェル  | Electron 33+                                 |
| エディタ | Monaco Editor                                |
| 共同編集 | **Yjs** + Monaco バインディング                     |
| P2P  | LAN は UDP 発見 + TCP 中継（フェーズ1）。WebRTC は後続オプション |
| 状態   | Zustand                                      |
| ビルド  | electron-vite                                |
| 配布   | electron-builder（NSIS）                       |
| AI   | Main から fetch + SSE。Agent は Main で tool ループ |


**Electron を選ぶ理由:** Monaco との相性、Windows パッケージの成熟、MVP 速度。

**後続の代替:** Tauri はバイナリは小さいが、Monaco + P2P のコストが高い。フェーズ1–2では採用しない。

### IPC（最小）


| チャンネル                                                         | 方向  | 用途                                                                |
| ------------------------------------------------------------- | --- | ----------------------------------------------------------------- |
| `fs:open` / `read` / `write` / `saveAs` / `identity` / `stat` | R→M | ファイル。`read` / `identity` は実体識別子 `fileIds` を返す。`stat` は共同編集の保存エコー用 |
| `collab:enable` / `startHost` / `join` / `leave`              | R→M | セッション。開いているファイルは `files-manifest` フレームで共有する（`setDocs` は無い）        |

Renderer は生のソケットや API Key を持たない。

## 12. まとめ

Coterea は Windows 上の **左エディタ・右パネル** のテキストアプリである。右パネルはフェーズ1では共同編集、フェーズ2では AI チャット（会話スレッド）が本体で、共同編集の操作は折りたたみに残す。

1. **フェーズ1** — タブで複数のテキストを開き、**サーバーなし P2P** でリアルタイム共同編集する。
2. **フェーズ2** — 利用者が繋いだ汎用 LLM と **Ask / Edit / Agent** でスレッド単位に対話し、承認した編集を **同じ CRDT 文書** に載せて全員で共有する。会話そのものは端末ローカル。Agent は開いているタブだけをツールで読む。

本質は「ローカルファイル + リアルタイムな人の共同編集 +（任意の）AI という共同編集者」である。
