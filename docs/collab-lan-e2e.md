# 共同編集 LAN E2E（手動）

フェーズ1の完了確認用。`npm test` では拾えない経路（同一 LAN、ファイル実体、ハブ交代、キャレット）を実機で通す。

| 項目 | 内容 |
|------|------|
| 対象 | 仕様 4.3 / 4.5（同一実体の同時編集、CRDT、キャレット、サーバーなし） |
| 単体テスト | `npm test`（同一性・ハブ選出・フレーム等）。本手順の代替にはしない |
| 所要 | 準備 15 分、本試験 20〜30 分 |

同一 PC の `npm run dev` と `npm run dev:2` はハブ交代や CRDT の机上確認に使えるが、**LAN・ファイアウォール・別パス表記の代わりにはならない。**

## 0. 準備（初回）

### 端末

- **PC-A / PC-B** — 同じプライベート LAN。ゲスト Wi-Fi・AP 分離は使わない。
- 両方に同じビルド（または同じ `main` の `npm run dev`）。
- **ファイル → 設定**で表示名を変える（例: `A` と `B`）。
- **表示 → 共同編集パネル**（`Ctrl+\`）を出す。

### ファイアウォール

初回は Windows の許可ダイアログで **プライベートのみ**。出ないときは「許可されたアプリ」で `Coterea.exe`（開発時は `electron.exe`）を UDP/TCP とも許可する。

| 用途 | ポート |
|------|--------|
| ピア発見 | **UDP 47821**（固定） |
| 文書同期 | ハブ側 **TCP**（起動のたびに変わる） |

### 共有ファイル（正本）

同じ名前のローカルコピー（どちらも `C:\work\a.md`）は **同期しない**。仕様どおり、双方から見える **SMB 共有上の同一実体** を開く。

例: PC-A の `C:\Share\coterea` を共有名 `coterea` にし、中に `notes.md` を1つ置く。エクスプローラーで両方から同じ中身が見えることを先に確認する。

| 役割 | 開き方（別パス表記用） |
|------|------------------------|
| PC-A | `\\PC-Aの名前\coterea\notes.md`（UNC） |
| PC-B | `net use Z: \\PC-Aの名前\coterea` のあと `Z:\notes.md`（マップドライブ） |

## 1. 自動接続と同時編集

1. PC-A だけ Coterea を起動し、UNC で `notes.md` を開く。状態は「一人で編集中」。共同編集セッションはまだ組まないのが正しい。
2. PC-B を起動し、マップドライブで同じ `notes.md` を開く。
3. **数十秒以内**に、どちらかが「ハブ（先にいた人）」、もう一方が「参加中」。右ペイン「共有中のファイル」に `notes.md` が出る。右上アバターが 2人。
   - つながらない → ハブ側の「待ち受け」をコピーし、相手で **IP:ポートで接続**。UDP が死んで TCP だけ生きている切り分けになる。手動でもだめならファイアウォールか別セグメント。
4. A がファイル先頭に `AAA`、B が末尾に `BBB` をほぼ同時に打つ。両方に両方入ること。上書きで片方消えたら失敗。
5. 2〜3秒待ってディスクを見る（メモ帳や `type`）。共有上の `notes.md` に両方入っていること（自動保存は約 800ms）。
6. 片方が Undo（`Ctrl+Z`）。**自分の入力だけ**戻り、相手の文は残ること。

**不合格の典型:** 接続はできたが「共有中」に出ない → 別実体を開いている。右ペインのヒントをそのまま記録する。

---

## 2. 別パス表記（ファイル同一性）

手順1が通った状態で、パスが UNC と `Z:\` で違うことを双方のタブ／エクスプローラーで確認する。同期していれば、パス文字列一致ではなく **実体一致** は合格。

### 陰性（必須）

1. 接続したまま、PC-B で **ローカル** `C:\Temp\notes.md`（中身はコピーでよい）を開く。
2. このタブは同期しない。共有の `notes.md` タブだけ同期すること。

同名だから混ざる、は仕様違反。

---

## 3. ハブ切断 → 引き継ぎ → 再参加

1. 右ペインで誰が「ハブ（先にいた人）」か確認する。先に起動した側のはず。
2. **ハブ側の Coterea を終了**する（パネルの「ハブを停止」でも可。本命はプロセス終了）。
3. 残った側が、数秒〜十数秒で自分からハブになる。編集を続けられ、ディスクにも残ること。
4. 切った側を起動し直し、同じ共有 `notes.md` を同じ開き方で開く。自動または手動で **ゲストとして** 戻る。
5. 終了中に残った側が足した文が、戻った側に **全文で載る**こと。戻った側の古いバッファと混ざって重複・欠落したら失敗（再接続時は正本のスナップショットで合わせる）。

---

## 4. キャレット残存（3プロセス）

2台のままでは「抜けた人のカーソルが消える」と「残った人のカーソルも消える」を分けられない。

1. PC-A で2つ目を起動する。
   - 開発: その PC で `npm run dev:2`（別 user-data-dir）
   - 製品インストーラは同時起動しにくいので、2つ目は開発起動でよい
   表示名を `A2` にする。
2. A / A2 / B の3つが同じ共有 `notes.md` を開き、3色のリモートキャレットが見えること。
3. **A2 だけ終了。** A から見て **B のキャレットが残る**、B から見て **A のキャレットが残る**。抜けた A2 の色だけ消える。
4. 3人全員のカーソルが消えたら失敗（離脱時に Awareness を消しすぎ）。

---

## フェーズ1として通したと言える条件

全部を **同じ日・同じビルド** で満たす。

- 共有ファイルが数秒以内に双方向反映される
- UNC とマップで同期し、ローカル同名は同期しない
- ハブ終了後に残りがハブになり、再参加で内容が揃う
- 3人中1人が抜けても、残る2人のキャレットは消えない
- Coterea 用の自前サーバーは立てていない
